## Current position

**Phase 1a complete, verified end-to-end. Phase 1b in progress (8 of 10 tasks done).**

All 13 tasks of `docs/plans/2026-08-21-phase-1a-implementation-plan.md` are
done. The full walking skeleton — intake → DMN determination (persisted
trace) → hash-chained audit → dbt bronze/silver/gold → Metabase dashboard —
runs against real infrastructure end to end, proven automatically by
`data-platform/tests/test_end_to_end.py` (`make e2e`, and CI's `e2e` job on
every push) and walkable by hand via `docs/demo.md`. Every item in the
plan's own "Phase 1a definition of done" checklist is satisfied — see
Task 13's verification-log row below for how each one was actually
checked, not just asserted.

Phase 1b's design decisions are recorded in
`docs/design/2026-08-22-phase-1b-hardening-design.md` (see the "Decisions
already made" table below), and its 10-task implementation plan is written:
`docs/plans/2026-08-22-phase-1b-implementation-plan.md`.

**Phase 1b, Task 1 (Keycloak) is done** — real OIDC login (two realms,
Authorization Code + PKCE) has replaced `HardcodedRoleFilter` end to end,
verified against a real Keycloak (Testcontainers in the Java suite, the
real `infra/docker-compose.yml` service manually) including a live-browser
click-through of both the citizen and worker login paths. See Task 1's
verification-log row below.

**Phase 1b, Task 2 (row-level authorization) is done** — `case_assignment`
and `worker.role`'s `SUPERVISOR` value (both dormant since Phase 1a) now
gate real access: a `WORKER` auto-claims an unassigned household on first
view and is denied outright on one already claimed by someone else; a
`SUPERVISOR` can view any household, with the override logged via
`CASE_VIEWED`'s new `in_assignment` payload field rather than blocked; a
new `SupervisorController` adds explicit reassignment and sensitive-case
flagging. See Task 2's verification-log row below.

**Phase 1b, Task 3 (mock external verification interface) is done** — the
dormant `verification` table (seeded since Phase 1a's Task 2, never
written to) now gets a real `OUTSTANDING` `INCOME` row on every intake
submission; a new `MockVerificationService`/`VerificationController` pair
lets a worker request and synchronously resolve one, writing the
genuinely new `verification_response` table (outcome + raw mock payload)
and moving `verification.status` to `RECEIVED`. FTI-style safeguards from
the design doc are concrete, not asserted: every request/resolution is a
`VERIFICATION_UPDATED` audit-chain event pair (`REQUESTED` then
`RECEIVED`); both new endpoints are gated by the exact same caseload check
Task 2 built, promoted from a `WorkerCaseController`-private method to a
shared public one on `CaseAssignmentService` so both controllers enforce
one policy, not two copies of it; and `VerificationStatusResponse`
structurally has no field for the raw payload, so it cannot leak through
that shape regardless of caller. See Task 3's verification-log row below.

**Phase 1b, Task 4 (Airflow orchestration) is done** — a new `canopica_pipeline`
DAG (`infra/airflow/dags/canopica_pipeline_dag.py`) runs the same four stages
`make pipeline` already ran by hand (extract → dbt build → materialize →
provision Metabase), calling the identical underlying functions, on its
own `@hourly` schedule. Three new Compose services (`airflow-init`,
`airflow-webserver` on `:8082`, `airflow-scheduler`, `LocalExecutor`,
metadata on a new `airflow` database/role on the shared `postgres`
service). Verified for real: a manually-triggered run and `test_airflow_dag.py`'s
own independently-triggered run (via Airflow's REST API, not the CLI) both
reached every task in `success`, confirmed against the live stack three
times total across this task's work. See Task 4's verification-log row
below for the real dependency conflicts this uncovered and how each was
resolved.

**Phase 1b, Task 5 (full medallion coverage) is done** — bronze widened
from Phase 1a's seven tables to fourteen (design doc §3.4.2's full list,
plus `application`/`benefit_month`, a plan gap `fct_application`/

**Phase 1b, Task 6 (reporting widened) is done** — real
`program_request.is_expedited` (7 CFR 273.2(i), previously always `false`)
